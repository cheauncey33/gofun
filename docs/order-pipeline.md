# 订单链路

## 接单

1. 校验活动、票档、限购和幂等键。
2. Redis Lua 原子预扣库存并保存预扣凭证。
3. MySQL 事务写入订单、订单明细和 Outbox。选座订单在事务中占座。
4. 返回订单号和 queued 状态。

## 确认

Outbox 发布器分批领取事件，提交领取事务后发送 RabbitMQ 并等待发布确认。一批全部确认后用一条 SQL 更新成功状态；中途失败允许重投，由消费去重处理。
固定数量的消费者处理订单，事务内完成库存扣减、消费去重和 pending_payment 状态更新，提交后 ACK。
Consumer 先锁定订单，再用一次聚合查询读取明细数量、总票数、票档和已占用座位数，统一核对消息凭据。普通订单的凭据读取为两次 SELECT；分桶库存扣减后的余量查询仍用于判断售罄边界。
默认 12 个 Consumer、4 个 Publisher。Worker 数决定处理并发，prefetch 决定每个消费者领取的未确认消息上限。

经营漏斗从订单和候补记录聚合，查询结果缓存 20 秒。

## 支付到期

扫描器每 10 秒按 expires_at、id 分页读取到期订单，每批 100 条。
关单事务与支付事务使用一致的加锁顺序，并在锁内核查订单状态和支付期限。
查询使用 status、expires_at、id 联合索引。

## 恢复

订单恢复 Worker 统一启动、停止和管理异常核查与库存归还。内部超时循环每 10 秒扫描未支付订单；恢复循环每 30 秒处理超时预扣、悬挂退款和到期归还任务，每 5 分钟检查库存差异。两个循环独立执行，避免退款查询阻塞超时关单。
查询失败保留原待处理记录，下轮继续核查；只有确认需要归还库存时才创建归还事件，执行失败更新原事件的重试状态。
取消、超时、下单失败和退款收尾，在更新业务状态的同一 MySQL 事务里写入 Outbox 的 `ticket.stock.return` 事件。
Worker 每次通过 `FOR UPDATE SKIP LOCKED` 领取一条到期事件，执行 Redis Lua，成功后标记 `completed`；失败记录错误、尝试次数和下次执行时间，最多尝试 12 次。
归还使用订单号和归还类型生成幂等 token。Redis 已归还而数据库提交失败时，重试通过 token 去重。归还任务完成后去重标记保留 7 天；未完成任务的标记保持有效。
预扣恢复先查 MySQL 订单：存在则确认 Redis 凭证；不存在则事务写入隐藏的恢复标记订单和归还事件。恢复标记与正常下单使用相同的订单主键，因此正在提交的订单与恢复动作只有一方能成功。
库存对账输出差异日志和指标，由核查后的修复操作处理。
启动预热仅初始化缺失的 Redis key，并跳过未完成库存归还事件涉及的 key。Redis 库存或去重数据整体丢失时，需要暂停售卖并根据数据库与未完成任务核查重建。

## 支付与退款

支付回调验签、核对金额，在事务中锁定支付记录和订单，更新为已支付并生成电子票。重复回调按支付状态处理。
超时扫描在取得相同的业务锁后核查支付期限，防止支付与关单同时成功。
退款先持久化 `refunding`，再于事务外调用网关；成功后事务更新为已退款、作废电子票、恢复数据库库存并登记库存归还事件。
超过两分钟仍处于 `refunding` 的订单，由同一个后台 Worker 重驱动。当前沙箱网关按支付单号幂等处理退款。

## 验证

性能比较使用相同的请求分布和资源配置，记录接口受理吞吐、最终订单确认吞吐、P99、事务耗时、连接池等待和 MQ 积压变化。
正确性检查覆盖重复消费、库存上限、支付关单竞争和预扣恢复竞争。
