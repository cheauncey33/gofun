## 项目连续追问示例

题目: 你说用 Redis Lua 防超卖，具体怎么做？

连续追问:

1. Lua 脚本里检查了哪些 key？
2. 普通下单和秒杀的 Lua 有什么不同？
3. Redis 扣完后 MySQL 还会不会失败？
4. MySQL 失败后 Redis 怎么恢复？
5. 如果恢复也失败怎么办？

收口回答:

当前项目实现了 Redis 前置扣减、MQ 失败立即回滚、consumer 失败重试和普通库存定时补偿。它不是完整分布式事务，生产环境我会加本地消息表、死信队列、重试上限、补偿记录和告警。

## 不知道时的收口话术

- “这个点项目当前没有实现，我不能把它说成已经做了。我的理解是生产上可以这样补……”
- “我现在能确认的是代码里做了 A 和 B，C 属于后续增强。”
- “这个问题如果落到我的项目，风险点主要在……我会优先从日志、指标和数据一致性三个方向排查。”
